# LxPilot

Нативный клиент macOS (SwiftUI) для ядра [sing-box-lx](https://github.com/Leadaxe/sing-box-lx) с интерфейсом в духе FlClash: боковая навигация, панель из карточек, плавающая кнопка запуска с таймером, группы прокси плиткой.

> Статус: v0.1. Собирается Xcode 27 / Swift 6.4 в режиме Swift 5. На живом Mac проверен сценарий без TUN: движок lxd, Clash API, системный прокси. TUN, движок `classic`, смена профиля на ходу и импорт подписок пока не проверялись.

## Сборка

Нужны macOS 13+ и Xcode 15+ (или Command Line Tools со Swift 5.9+). Сторонних зависимостей нет.

```sh
./build-app.sh          # → build/LxPilot.app (ad-hoc подпись)
open build/LxPilot.app
```

Для разработки: `open Package.swift` (откроется в Xcode) или `swift run`.

## Первый запуск

1. **Инструменты → Скачать последний релиз** — приложение берёт `sing-box-…-darwin-arm64/amd64.tar.gz` из релизов Leadaxe/sing-box-lx, сверяет с `SHA256SUMS` и кладёт бинарь в `~/Library/Application Support/LxPilot/bin/`. Можно указать свой файл.
2. **Профили → Добавить** — URL подписки, готовый конфиг sing-box (JSON, допускаются комментарии) или ссылки `vless://`, `trojan://`, `ss://`, `hysteria2://`.
3. Кнопка ▶ в правом нижнем углу.

## Что умеет

| Раздел | Содержимое |
| --- | --- |
| Панель | график скорости, режим Rule/Global/Direct, трафик за сеанс, переключатели TUN и системного прокси, внешний IP, версия ядра и память |
| Прокси | группы selector/urltest, выбор узла, проверка задержки по группе и всех сразу |
| Профили | подписки с обновлением, остаток трафика и срок из `subscription-userinfo`, локальные конфиги |
| Соединения | таблица активных соединений с цепочкой и правилом, поиск, закрытие |
| Логи | поток лога ядра с фильтром по уровню и поиском |
| Инструменты | установка ядра, движок, порты, стек TUN, автозапуск, тема и акцент |

Плюс элемент в строке меню: текущая скорость (сверху отдача, снизу загрузка) и два мини-графика за последние 12 секунд; в меню — подключение, TUN, системный прокси, режим. Вид переключается: только значок / скорость / скорость и графики.

## Как устроено

- **Движок `lxd` (по умолчанию).** Ядро запускается как `sing-box lxd --state-dir … --config-force … --run` в loopback-режиме (`tls: false` + случайный Bearer-секрет в `daemon.json`). Смена профиля уходит в `POST /admin/apply`: демон проверяет конфиг, подменяет ядро и сам откатывается на last-good при сбое — процесс и канал управления при этом не перезапускаются.
- **Движок `classic`.** Обычный `sing-box run`; любое изменение — перезапуск процесса. Запасной вариант, если с lxd что-то не так.
- **Данные интерфейса** идут через Clash API ядра (десктопные сборки lx собраны с `with_clash_api`): приложение само вписывает в конфиг `experimental.clash_api` на `127.0.0.1` со случайным секретом.
- **Оверлей конфига.** Поверх профиля подставляются `clash_api`, `cache_file`, уровень логов и входящие: `mixed` на `127.0.0.1:7890` и, при включённом TUN, `tun` (если в профиле есть свой `tun`, берётся он). Отключается галочкой «Управлять входящими».
- **Ссылки → конфиг.** Для списка ссылок собирается полный конфиг: `selector` + `urltest`, sniff, перехват DNS, правила `clash_mode`. Поддержаны lx-расширения: транспорт `xhttp` (`mode`, `host`, `path`) и VLESS `encryption`.
- **TUN.** На macOS для TUN нужен root. Приложение показывает системный запрос пароля и запускает ядро от root; небольшой сторож останавливает его при выключении TUN или выходе из приложения (второго запроса пароля нет). Перед запуском ядро копируется в принадлежащий root каталог штатной командой `lxd --service=copy --exec-dir /Library/PrivilegedHelperTools/LxPilot`; если версия ядра этого не умеет, запускается копия из папки приложения.
- **Системный прокси** ставится через `networksetup` на все активные сетевые службы и снимается при отключении, выходе и при следующем запуске после аварийного завершения.

## Ограничения v0.1

- Нет редактора правил и DNS: маршрутизация берётся из профиля или из встроенного шаблона (всё через прокси, частные сети напрямую).
- Параметр `extra` в ссылках xhttp, WireGuard/AmneziaWG-ссылки и `.conf` не разбираются — такие узлы добавляйте готовым JSON.
- Имя поля состояния в ответе `/admin/status` в документации lxd не зафиксировано, поэтому оно ищется по значениям `idle|started|fatal`; готовность ядра определяется по ответу Clash API.
- Специфичные для lx данные по gRPC (`GetPool`, `GetChains`, поток DNS-запросов) не используются.
- Скрипт запуска от root лежит в папке приложения, доступной пользователю на запись. Для личного Mac это приемлемо; более строгий вариант — системная служба `sudo sing-box lxd --service=install` с mTLS-сопряжением — пока не реализован.
- Определение внешнего IP обращается к стороннему сервису ipwho.is через прокси.

## Данные

`~/Library/Application Support/LxPilot/`: `bin/` (ядро), `profiles/`, `runtime/` (итоговый `config.json`, кэш), `lxd-user/` и `lxd-root/` (состояние и `lxd.log` демона), `settings.json`.
